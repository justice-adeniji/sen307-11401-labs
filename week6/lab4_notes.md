# Lab 4 – Foreign Key Constraints and Referential Integrity

In Part 4, I encountered **Error 1451**, which occurs when attempting to delete a parent record that is still referenced by a child record through a foreign key constraint. MySQL refused to delete the department because the student with matric number `20239999` was still assigned to the department. This restriction protects referential integrity and prevents orphaned records in the database. I fixed the problem by first updating the student's department to Software Engineering and then deleting the Library and Information Science department. Another possible solution would have been to delete the dependent student before deleting the department, although this would result in losing the student's record. Alternatively, a foreign key configured with `ON DELETE CASCADE` could automatically delete dependent student records, but that would not be appropriate when we want to preserve student information.
